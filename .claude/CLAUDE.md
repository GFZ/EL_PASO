# EL-PASO

Python framework (GFZ Helmholtz Centre for Geosciences) for downloading, processing, and standardizing satellite particle-observation data for radiation-belt modeling.

## Stack
- Python 3.12+, dependency management via `uv` (`uv.lock`).
- Build backend: `hatchling`, with a custom build hook (`hatch_build.py`, `_irbem_build.py`) that compiles the IRBEM Fortran library into `libirbem.so` at install time. This is why install is not a plain `pip install`.
- CLI (`el-paso` / `ep`) is generated by `typer`: one sub-command group per mission, one sub-command per recipe.
- Each agent shell command starts fresh, so an activated venv does not carry over. Call tools as `.venv/bin/python`, `.venv/bin/ruff`, `.venv/bin/ty`, `.venv/bin/el-paso`, etc.

## Layout
- `el_paso/` is the package: `cli/`, `data_standards/` (PRBEM/GFZ standards), `dataset/`, `processing/` (algorithms, incl. `magnetic_field_utils/irbem.py`), `recipes/<mission>/` (one subpackage per satellite mission, plugin-style), `saving_strategies/` (output writers).
- `tests/unittests/` mirrors `el_paso/`'s subpackage layout; `tests/system/` uses Zenodo-hosted reference data.
- `docs/`: mkdocs-material site (built by ReadTheDocs). `tutorials/`: numbered Jupyter notebooks. `scripts/`: SLURM/ops helpers. `hooks/`: local pre-commit hooks.

## Rules
- **Never run the full pytest suite.** Run only the tests covering the files you changed; see the `build-test-verify` skill for how to find them.
- **Never run `bumpver` or otherwise cut/tag/push a release.** That is the user's call only, never an agent's.
- Both rules above are enforced by a PreToolUse hook (`.claude/hooks/guard_bash.py`), which blocks unscoped `pytest` and any `bumpver` command.
- Every new/changed source file needs an SPDX header (dual-licensed Apache-2.0 / LGPL-3.0-only, REUSE-compliant). See `create-pull-request`.
- Never hand-edit code between `# BEGIN GENERATED` / `# END GENERATED` markers, or docstring lines between `<!-- BEGIN GENERATED ... DOCS -->` / `<!-- END GENERATED ... DOCS -->` markers (in `el_paso/typing.py`, `el_paso/dataset/metadata.py`, `el_paso/dataset/dataset_implementations.py`). Change the data standard and let `hooks/generate_metadata_stubs.py` regenerate them. Enforced by its own PreToolUse hook (`.claude/hooks/guard_generated_markers.py`), which blocks any `Edit`/`Write` that would change content inside one of these blocks.
- Public symbols are exported lazily via `lazy_loader`. Adding one means editing both halves of its package's `__init__.py`, plus the API docs page (see `export-public-api`).
- Keep `import el_paso` cheap. Import heavy third-party packages (xarray, pandas, cdflib, scipy, IRBEM wrappers, ...) inside the function that needs them, with `# noqa: PLC0415`, or under `if TYPE_CHECKING:` when only used in annotations. Don't add them as module-level imports on the `import el_paso` path.
- When running a recipe, always pass `--raw-data-path` and `--processed-data-path` pointing outside the repo. Both default to `.`, and `.mat`/`.h5` outputs are not gitignored, so a run from the repo root leaves untracked data files that could get committed. Use `--dry-run` to check a recipe's arguments without downloading anything.
- Credentials (`CLIENT_ID`/`CLIENT_SECRET`, `ERG_USER`/`ERG_PASSWORD`, `SPACETRACK_USER`/`SPACETRACK_PASS`) come from environment variables. Never print, log, or commit their values. The other `EL_PASO_*` variables are listed in `.claude/agent-guides/architecture.md`.
